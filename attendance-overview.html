1. できること

練習や大会の前に、「今日は誰が来るの？」を確認して、くみあぷ（PairGen）に 1 人ずつ入力し直していませんか。この機能は、その手間をなくします。

みんなが Web 上の出欠表に「行きます」「行けません」を入力しておくと、くみあぷ（PairGen）がその出欠表を読み取って、来る人だけをプレイヤー一覧に並べてくれます。

参加者が Web アプリで出欠を入力しておくと、くみあぷ（PairGen）の「グループ読込」だけで、次のイベントの参加者をプレイヤー一覧に取り込めます。名前を 1 人ずつ入力したり、当日に出欠を聞いてチェックを入れ直したりする手間がなくなります。

  • 出欠を「出場」「休憩」「欠席」に自動で振り分けます。
  • プレイヤー一覧の見出しに、グループ名とイベントの日付を表示します。
  • Web アプリで登録したレベル（1〜3）も反映されます。

この方法の良いところと、引き換えのこと

  • 良いところ：Google のアカウントさえあれば、無料で運用できます。普段から使い慣れた Google のサービス（ドライブ・スプレッドシート）の上で動くので、データの置き場所や中身が分かりやすく、専用のサーバーを借りる必要もありません。
  • 引き換えのこと：最初の設定が少し面倒です。スプレッドシートのコピー、キーの設定、公開、権限の承認と、パソコンで何段階かの操作が必要です。ただし、これは最初の 1 回だけです。設定が済めば、あとは参加者が出欠を入力し、くみあぷ（PairGen）が読み込むだけです。
想定している規模：週 3 回ほど練習があるグループで、メンバー 30〜50 人なら余裕をもって使えます。100 人前後までは使えますが、画面の表示や登録の遅さが目立ち始めます。根拠は7. 想定している規模と、その根拠にあります。
はじめに必要なもの
  • 管理者には Google アカウントが必要です。
  • 最初の設定（スプレッドシートのコピーと公開）は、パソコンのブラウザで行います。スマートフォンやタブレットでは、Apps Script の画面が操作しにくく、設定が難しいためおすすめしません。
  • 設定が済んだあとは、参加者の出欠入力も、くみあぷ（PairGen）での読み込みも、スマートフォンだけで行えます。

2. 仕組みと役割

登場するのは 3 つです。

① 参加者スマートフォンなどで、Web 上の出欠表に出欠を入力する
→
② 出欠表（Web アプリ）入力された出欠をためておく場所。管理者の Google ドライブに置く
→
③ くみあぷ（PairGen）出欠表を読み取って、プレイヤー一覧を作る

② の出欠表は、Google スプレッドシートと、それに付属する Web アプリ（Google Apps Script）でできています。くみあぷ（PairGen）は出欠表を読むだけで、書き込みはしません。

出欠表は、管理者が最初に 1 回だけ用意します（自分の Google ドライブにコピーして、公開する作業です）。専門的に見えますが、手順どおりに進めれば難しくありません。

役割やることページ
管理者（最初に 1 回・パソコンで）スプレッドシートをコピーし、公開（デプロイ）して、URL とキーを用意する管理者の作業
管理者（くみあぷ（PairGen）を使う人）くみあぷ（PairGen）にグループとして登録し、読み込むユーザーの作業
参加者Web アプリで名前を登録し、イベントの出欠を入力するユーザーの作業

流れは次のとおりです。

  1. 管理者がスプレッドシートを用意して公開する
  2. 管理者が参加者に Web アプリの URL とキー（ACCESS_KEY）を伝える
  3. 参加者が Web アプリで名前を登録し、イベントの出欠を入力する
  4. 管理者が くみあぷ（PairGen）の「グループ読込」で、出欠を取り込む

3. 出欠の反映のされ方

Web アプリでの出欠くみあぷ（PairGen）での状態
参加出場
保留休憩
未回答・不参加デフォルト欠席

読み込む対象は、今日以降で一番近いイベント 1 件です（今日のイベントも含みます）。

今日以降のイベントがまだ登録されていないときは、出欠にかかわらず全員が出場になり、見出しはグループ名だけになります。

4. もう一度読み込むと

  • 同じグループ・同じイベント日で読み込み直すと、試合の記録（試合数・連続回数・固定ペア・対戦履歴）は残したまま、名前・レベル・出欠だけが更新されます。試合の途中で誰かの出欠が変わったときに使えます。
  • 後から Web アプリに加わった人は、一覧の末尾に追加されます。Web アプリから居なくなった人は、消さずにデフォルト欠席になります。
  • 別のイベント日、または別のグループを読み込むと、一覧が入れ替わります。試合の記録が消えるので、試合が進んでいるときは確認が出ます。
更新したあとの変更は、進行中の試合には影響せず、次の組み合わせから反映されます。

5. 知っておくこと

  • スプレッドシートから取り込んだ人は、くみあぷ（PairGen）のメンバーDB（登録メンバー）には保存されません。読み込むたびにスプレッドシートから作ります。
  • そのためグループ管理で、メンバーを手動で登録することはできません。
  • 写真は引き継がれません。
  • くみあぷ（PairGen）から Web アプリへ書き込むことはありません。出欠の入力は Web アプリで行います。
  • 2 年より古いイベントと出欠は、Web アプリ側で自動的に削除されます。
  • インターネットに接続していないと読み込めません。

6. 困ったとき

表示原因と対処
「READ_KEY が正しくありません」READ_KEY が違うか、未設定です。管理者の Apps Script「スクリプト プロパティ」の値を確認して、くみあぷ（PairGen）のグループ編集（鉛筆アイコン）で入れ直します。
「スプレッドシートの URL が正しくありません」https:// で始まる、/exec で終わるウェブアプリの URL を入れます。スプレッドシート自体の URL や、Apps Script エディタの URL ではありません。
「スプレッドシートから返されたデータを読み取れませんでした」URL が別のページを指している可能性があります。管理者の作業の「URL を確認する」を見直してください。
参加者が Web アプリを開くとエラーになる、またはくみあぷ（PairGen）で読み込めない（設定した直後から）管理者が、Web アプリを自分で開いて権限を承認する作業（2 回目）を忘れている可能性があります。管理者が、ウェブアプリの URL を自分のブラウザで開いて承認してください。くみあぷ（PairGen）では、「スプレッドシートから返されたデータを読み取れませんでした」と出ることがあります。手順は管理者の作業の「6. ウェブアプリを開いて権限を承認する」です。デプロイし直したり、コピーし直したりしたあとも、同じ確認をしてください。
読み込みに時間がかかるしばらく使っていないと、最初の 1 回は数秒かかることがあります。
出欠が反映されないWeb アプリで、その人が名前を登録し、イベントの出欠を押しているか確認してください。未回答は欠席になります。
READ_KEY を変えたときは、くみあぷ（PairGen）のグループ編集で新しい値に差し替えます。Apps Script の再デプロイは不要です。鍵が外に漏れたときも、同じ手順で変更できます。

7. 想定している規模と、その根拠

練習が週 3 回あるグループを前提にした見積もりです。実測ではなく、仕組みからの見積もりです。出欠データの量の見積もりは、画面を開くときに読む範囲を絞る前の考え方を含みます。Google 側の上限の数値は目安なので、最新の値は Google の公式ドキュメント「Apps Script Quotas」で確認してください。

メンバー数ごとの見込み

メンバー数見込み
30〜50 人余裕
100 人前後まで使えるが、画面表示や登録の遅さが目立ち始める
200 人超作り直し（またはデータの読み方の見直し）が必要

データ量の見積もり（2 年保持）

  • イベントは年に約 156 件（週 3 回）で、2 年分で約 310 件です。
  • 出欠の行数は「メンバー数 × イベント数」が上限です（同じ人の出欠は上書きされるので、それ以上は増えません）。
メンバー数出欠データの行数（上限）
50 人約 1.5 万行
100 人約 3 万行

遅くなる原因

  1. 画面を開くたびに、出欠データを読む。画面を開いたときに読むのは、先月 1 日から翌月末日まで（今日を基準にした、当月の前後 1 か月）のイベントと出欠だけです。ほかの月は、カレンダーでその月を開いたときに、その月の分だけ読み込みます（読み込み中は日付をタップできません）。そのため、データが 2 年分たまっても、画面を開くときの重さはほとんど増えません。出欠を登録するときにも、既存の行を探すために読みます。
  2. 書き込みは 1 件ずつ順番に処理される。待てるのは最大 10 秒で、1 件に 1〜2 秒かかります。そのため「練習の案内の直後に 20 人が同時に押す」ような場面では、後ろの人が待たされたり、失敗したりします。50 人規模なら、実際に同時になるのは数人で、ほぼ問題ありません。

Google の利用量の上限（クォータ）

クォータは、Google が Apps Script などに設けている利用量の上限です。共用のサーバーを一部の人が使いすぎないための仕組みで、超えるとその日（または一定時間）は実行が失敗します。

項目無料アカウントの目安このしくみでの意味
1 日の合計実行時間約 90 分画面を開く・出欠を登録するたびに加算されます。1 回 2 秒なら、1 日 2,000 回以上使えます
1 回の実行の最大時間6 分通常は数秒なので問題ありません
同時に動く実行数3031 人目は待たされるか、失敗します
スプレッドシートの作成数など1 日あたり上限ありデータ用ファイルの作成は数回だけなので問題ありません
  • アカウントの種類（無料の Gmail か Google Workspace か）で、数値は変わります。
  • 超えると「サービスの呼び出し回数が多すぎます」のようなエラーになり、翌日（上限によっては数分〜数時間後）に回復します。週 3 回・50 人程度なら、ふつうは上限に近づきません。
  • くみあぷ（PairGen）の読み込みも、1 回ごとにスプレッドシートを開きます。必要なときだけ読み込み、何度も続けて読み込むのは避けてください。
Web アプリは、画面を開くときに読むイベントを、先月 1 日〜翌月末日に絞っています。
